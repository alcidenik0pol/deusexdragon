**what_it_does:** A 3D cyberpunk exploration game where players interact with NPCs via LLM-generated dialogue to complete quests and progress through levels.

**date:** Apr 2025 – Aug 2025

**stack:** TypeScript, JavaScript, Babylon.js 7.52.2, Babylon.js GUI, Babylon.js Loaders, Babylon.js Materials, Webpack 5, webpack-dev-server 4, TailwindCSS 3.4.17, PostCSS 8.5.3, autoprefixer 10.4.21, ts-loader 9, css-loader 6, style-loader 3, html-webpack-plugin 5, copy-webpack-plugin 11, OpenRouter API, Google Gemma 3 27B, Qwen 3 14B, OpenAI GPT OSS 20B, DeepSeek Chat v3, DeepSeek R1, GLB/GLTF model format, JSON metadata schema, ray-casting collision detection, light clustering algorithm, finite state machine for NPC behavior, server-sent events streaming, grid-based coordinate system

**built:** Implemented from scratch: custom light clustering system limiting 3 active lights per mesh with frustum culling and ray-cast occlusion detection updating every 10 frames. Built third-person camera with ray-cast collision detection, 6-unit max distance, and three profiles (third-person offset 0,2.5,4; NPC-focus offset 0,2.15,2.2; waiting offset 0,2.2,2.2). Implemented NPC state machine with 4 movement patterns (circle, figure-8, oval, infinity), state transitions between IDLE/WALKING/LOCKED, and configurable timers (2-5s pause, 4-8s walk, 15-30s pattern switch). Built multi-model LLM dialogue system supporting 6 models with per-model temperature (0.5-0.8), max_tokens (800-1200), and history_length (4-8) configurations. Implemented quest resolution system evaluating conversation history via LLM with 1-second async delay. Built 5 levels (singapore6, nightclub, taiyong, grid, credits) with modular file structure (buildings.js, lighting.js, npc.js, quest.js, furniture.js, objectMapping.js per level). Implemented component system with BaseComponent, BuildingComponent, WallComponent, DoorComponent, FloorComponent, SkyboxComponent. Built effect manager handling fog, rain (3 variants), volumetric light, and nightclub panel effects. Implemented music manager with 30-second transition delay and 2-second fade duration.

**hard_part:** Light clustering required balancing shader compatibility (max 3 lights per mesh) against visual quality; solved by implementing distance-sorted priority queue with frustum dot-product filtering and wall occlusion ray-casting, updating selection every 10 frames to reduce CPU overhead while maintaining 60fps. Camera collision required preventing clipping through geometry without using physics engine; solved by ray-casting from character to desired position and snapping to hit point with 0.2-unit offset. Multi-model LLM support required handling models with and without system message capability; solved by abstracting prompt construction with `supportsSystemMessages()` check and embedding context in user message for unsupported models. Character animation state changes required frame-accurate transitions; solved by pre-loading 7 separate meshes (idle, forward, backward, left, right, run, dance) and toggling visibility rather than blending animations on single mesh. Water rendering required balancing quality against performance; reduced render target from default 512px to 256px with 32 subdivisions.

**why_it_matters:** Proves ability to architect modular game systems with custom rendering optimizations, integrate multiple external LLM APIs with model-specific configurations, and implement real-time collision detection without physics engine dependency. Relevant for: SWE, FDE.
